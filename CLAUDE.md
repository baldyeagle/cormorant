# Cormorant

Personal WebKit browser for iPhone (first), macOS (second), iPad (later), replacing Arc / Arc Search for its owner, Austin Baldwin. Not a product: no accounts, no telemetry, no analytics, no server. AI features use the user's own API keys. Arc-style Spaces and "Browse for Me" are the reference points; AI usefulness is the differentiator.

## Layout

```
apps/ios/            Xcode 27 project: Cormorant app + CormorantShare extension + CormorantTests + CormorantUITests
apps/macos/          Xcode 27 project (CormorantMac.xcodeproj, scheme CormorantMac): the Mac app, sandboxed
apps/site/           cormorant.baldyeagle.dev (Astro 7 + Tailwind 4, deployed with Wrangler)
packages/CormorantKit/   Swift package: CormorantCore, CormorantBlocking, CormorantBrowser (the engine: store, tabs, web views), CormorantAI, CormorantSync (+ CormorantTestSupport, tests only)
assets/brand/        source artwork + make-icons.swift (regenerates app icons and favicons)
scripts/             repo scripts (default-browser plist checklist, UI test shards, quarantine, flake report)
docs/                gitignored, local-only: research, scope decisions, docs/product/todo.md (plan of record)
Cormorant.xcworkspace   opens apps/ios and the package together
```

## Commands

```
mise install                         # pins node, pnpm, vite-plus (vp)
pnpm install --frozen-lockfile
vp run build | vp run test           # site + package
vp run site:dev                      # Astro dev server
vp run kit:test                      # swift test --package-path packages/CormorantKit
CORMORANT_LIVE_TESTS=1 vp run kit:test   # also downloads + compiles the real filter lists (~15s)
vp run ios:build                     # simulator build, signing off
vp run mac:build                     # Mac app build, signing off
vp run ios:test                      # app tests + UI tests on a simulator (IOS_TEST_DESTINATION overrides the device)
scripts/check-default-browser-plist.sh [path/to/Cormorant.app]
```

Simulator builds need an iOS 26+ runtime. Device builds and TestFlight need Xcode signed into Austin's Apple ID and a registered device; the TestFlight recipe is `xcodebuild archive ... -allowProvisioningUpdates` then `-exportArchive` with an ExportOptions.plist (method `app-store-connect`, destination `upload`, `manageAppVersionAndBuildNumber` true). `xcrun simctl openurl` with an http(s) URL goes to the system default browser, not Cormorant; use `cormorant://open?url=...` to drive the app.

## Conventions

- Swift 6.4, strict concurrency. The app target uses `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and approachable concurrency, and so does the package's CormorantBrowser target (`.defaultIsolation(MainActor.self)` and the same upcoming features); the package's other targets do not.
- The browser engine (`BrowserStore`, `TabSession`, downloads, favicons) is CormorantBrowser, shared by the apps and built for iOS and macOS. What differs by platform comes from the app: app-wide through `BrowserPlatform`, per tab through `TabChrome` (the iPhone's are `IOSBrowserPlatform` and `IOSTabChrome`, the Mac's `MacBrowserPlatform` and `MacTabChrome`).
- The Mac app is sandboxed and has no app group (no share extension yet), so it gives the store a place for everything that would be in the group (state file, blocking's lists and preferences, settings): on a Mac the group's folder is found even without the entitlement, then can't be written. Its tabs are separate from the iPhone's. It hands no downloads to a system viewer (`DownloadCenter(handoffs: [])`). It shares the iPhone app's bundle ID, `dev.baldyeagle.cormorant`.
- iOS 26 / macOS 26 deployment targets. No third-party dependencies anywhere in Swift.
- Tests use Swift Testing (`import Testing`). Package tests run on macOS; WebKit APIs (`WKContentRuleListStore`, `WKWebView`) work there under `swift test`.
- A test goes in the lowest layer that can see what it checks. Logic that needs only package types (state in, text or a decision out) lives in CormorantKit and is tested there, where the macOS app will share it. App behaviour (`BrowserStore`, `TabSession`, WebKit, persistence across a relaunch) is tested in `apps/ios/CormorantTests`: Swift Testing hosted in the app (which shows an empty window when XCTest hosts it), every suite an extension of the serialized root suite `AppTests`, driving a real `BrowserStore` and real `WKWebView`s on `FixtureServer` pages through `TestBrowser` (`relaunch()` stands in for a kill and relaunch). Nothing is tapped and nothing reads the screen, so a loaded runner makes these slower, never wrong; wait with `TestBrowser.until`, never a sleep. A UI test is only for what only the screen shows (gestures, menus and sheets coming up, layout, focus) plus one end-to-end smoke per feature: rather than keep a UI test for a view's logic, lift the logic into a static function or CormorantCore. `FixtureServer` is CormorantKit's `CormorantTestSupport`, linked into both test targets and never into an app.
- UI tests (`apps/ios/CormorantUITests`) use XCTest's `XCUIApplication`. They launch with `-uiTesting` (debug builds: no saved tabs, state in a temp file, share inbox untouched, no filter lists fetched or installed) and load pages from `FixtureServer` on 127.0.0.1, so they need no network. A test that only needs to start on a page launches with `-uiTestingOpen <url>` (a tab there, as if saved) rather than typing it into the launch panel; not one about history or a new tab's first page, since a restored tab's load isn't a visit. Tap with `tapWhenSettled()`: it waits for the app's `UITesting.motion` probe to report no presentation or UIKit animation running (a tap mid-transition is dropped, and XCTest's idle check and an element's frame both miss a sheet still settling), then for the element to stop moving. Wait with `appears(within:)`, `disappears(within:)` and `waitUntil` (`Waiting.swift`), not `waitForExistence` or predicate expectations, which first check about a second in. Ceilings for something that should happen come from `Ceiling` (launch, load, ui) and are far above the slowest CI runner: they cost nothing when a test passes. Only checks that something _stays_ for N seconds use their own N. Don't make the waits check more often: each check is an accessibility snapshot of the app and its web content, and faster checking slowed page loads 2-4x on CI's 3-core runners. Never make an outcome depend on timing (a server delay racing a tap, a sleep before killing the app): have `FixtureServer` hold a request back, or wait on state the app reports under `-uiTesting` through `UITestingProbes` (saves landed, pasteboard text, how a pull ended); no `Thread.sleep` in tests. Test classes subclass `UITestCase`, which stops a test at its first failure and attaches a screenshot and the app's accessibility tree to it (CI records no video). XCTest's animation wait (`app.waitsForAnimations`) stays on except while a link context menu is up, so taps don't land mid-transition. CI runs the UI suite in five shards, with no retries (shard 1 also runs CormorantTests first); each builds the app, then boots its simulator (not both at once: that made a one-minute build take 7-13), then runs the tests `scripts/ui-test-shard.py` deals it, balanced by the CI times in `scripts/ui-test-durations.txt` (refresh with `--record`). The simulator has its wallpaper (PosterBoard), widget (chronod), App Store engagement, Health, mail/calendar account (dataaccessd) and Siri suggestion (siriinferenced) services disabled and XCTest's screen recording is off: both took the runner from the tests. Leave diagnosticd running: disabled, every process kept looking it up, thousands of failed lookups a second. A PR that touches nothing under `apps/ios`, `apps/macos`, `packages`, `scripts`, `.github` or the workspace skips the macOS jobs; add the `ui-stress` label to a PR (or run the workflow by hand) to run every test 5 times. A PR's new or renamed UI tests run 10 more times in their shards, and one failure fails CI, so a new test proves itself before it gates. A test that fails now and then goes in `scripts/ui-test-quarantine.txt` (date, test, reason), which takes it out of the gated shards for at most 14 days; past that the quarantine job fails CI, and the test gets fixed, moved to a lower-level test or deleted. Nothing is retried. A nightly run on main (08:23 UTC) runs every test 5 times, quarantined ones too. A failed shard lists its failed tests and their messages on the run's summary page; `scripts/flake-report.py` (needs `gh`) tallies UI test failures across the last 100 CI runs and names the tests that failed in 2 or more in 14 days as quarantine candidates. On the iOS 27.1 simulator a synthesized tap didn't activate SwiftUI menu items; pressing the menu's button and dragging onto the item does.
- Public package API is the contract between the package and the app. Add API freely; change existing signatures only with the app updated in the same change.
- The Xcode projects are `objectVersion = 90` with synchronized folder groups: new Swift files under `apps/ios/Cormorant/`, `apps/ios/CormorantShare/`, `apps/ios/CormorantUITests/` and `apps/macos/Cormorant/` need no pbxproj edits. Build settings like `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption` live in the pbxproj, not Info.plist, so Xcode edits don't drop them.
- Content blocking is on by default (EasyList, EasyPrivacy, EasyList Cookie). `ContentBlockingEngine.ruleLists(for:)` never blocks a navigation on network or compile; lists arrive via `listsVersion` / `onListsChanged`.
- Sync (CormorantSync, off by default): Spaces, profiles' names, open tabs, their folders and the tab archive (`BrowserState.shared`) are kept the same on every device through CloudKit's private database, each record sealed first (`SyncCipher`, AES-256-GCM, key in iCloud Keychain), so Apple sees only ciphertext. Incognito's tabs, blank tabs, which Space and tab are in front, and logins never leave the device. `SyncLedger` merges record by record, field by field, with no clocks (the cloud refuses a save over a copy it has replaced); it only deletes from the cloud what it saw being removed while the app ran, so a lost or reset state file deletes nothing. A folder is derived from its tabs: it's never deleted for going away here, only once no tab's record names it, and it's only sent with a tab that's in it. `SyncEngine` reads the state only while `BrowserStore.canSave`, so an unreadable state file is neither sent nor merged into. CloudKit and the Keychain are behind `SyncCloud` and `SyncKeyStore`: tests use `FakeSyncCloud` / `FakeSyncKeyStore` (CormorantTestSupport), and the real ones exist only in a signed build (`CloudKitSyncCloud.isAvailable`: never the simulator). Every build, local ones too, uses CloudKit's Production environment (`icloud-container-environment` in the entitlements), so a locally built app and a TestFlight one see the same data; a new record type or field has to be deployed to Production in CloudKit Console before a build that writes it. The switch is in Settings (`SyncSettings` on the iPhone, `SettingsWindow` on the Mac; wording in `SyncStatus`). A model field added to `Space`, `Tab`, `ArchivedTab` or `Profile` syncs with no extra work; a new kind of thing in `BrowserState` needs a record kind (`SyncRecordID.Kind`) and a place in `BrowserState.Shared`.
- Persistence: `BrowserState` is versioned JSON in the app group. An unreadable file is quarantined and the app must never auto-save over it (the "Start Fresh" flow).

## Default-browser entitlement checklist (hard constraints)

Apple's requirements (developer.apple.com/documentation/xcode/preparing-your-app-to-be-the-default-browser), enforced by `scripts/check-default-browser-plist.sh` in CI:

- `http` and `https` declared in `CFBundleURLTypes` (keep the existing `dev.baldyeagle.cormorant.web` entry exactly as is; the `cormorant` scheme is a separate entry).
- WKWebView only; never UIWebView.
- On launch, a URL/search text field is shown (the keyboard-up address field).
- Navigate straight to the requested URL; no interstitials or redirects. Safe-browsing warnings and native sign-in UI are allowed.
- Never add these Info.plist keys to any target: `NSPhotoLibraryUsageDescription` (use `NSPhotoLibraryAddUsageDescription` / `PHPickerViewController`), `NSLocationAlwaysUsageDescription`, `NSLocationAlwaysAndWhenInUseUsageDescription` (when-in-use is fine), `NSHomeKitUsageDescription`, `NSBluetoothAlwaysUsageDescription` (while-in-use is fine), `NSHealthShareUsageDescription`, `NSHealthUpdateUsageDescription`.
- Don't claim Universal Links for specific domains; the system ignores them for browsers.
- The `com.apple.developer.web-browser` entitlement was granted for `dev.baldyeagle.cormorant` (2026-10-28) and lives in `Cormorant.entitlements` (app target only, not the share extension); the checklist script fails if it goes missing.

## Process

- Do not commit, push, or deploy unless Austin asks. Branch work happens in T3 worktrees; `main` is fast-forwarded by merging PRs.
- Before any substantive commit, run at least one adversarial review pass with an Opus agent (give it the code and the brief, not conclusions), fix confirmed findings, then ask.
- `docs/product/todo.md` is the plan of record; keep it current when scope or status changes. It is local-only, like all of `docs/`.
- Site deploys (`vp run site:deploy`) and TestFlight uploads are outward-facing: Austin runs them or explicitly asks for them.
